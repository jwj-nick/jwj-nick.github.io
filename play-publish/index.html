Google Play 배포 가이드

개인 개발자 기준 · 단계마다 무엇을 왜 · 기준일 2026-08-10

이 문서의 목적: 개인이 만든 안드로이드 앱을 Google Play에 올리기까지 실제로 무엇을 해야 하고 왜 그것이 필요한지를 순서대로 정리한다. 사례는 render-ext의 Android 뷰어(현재는 GitHub Releases로 APK 직접 배포).

먼저 알아야 할 것 하나. 목적이 "설치할 때 뜨는 보안 경고와 '출처를 알 수 없는 앱 허용'을 없애는 것"이라면, 그건 공개 배포와 무관하다. 그 프롬프트는 사이드로딩(브라우저·파일 관리자로 APK 설치)이라는 경로에 붙는 것이라, Play가 설치를 대행하기만 하면 사라진다. 아래 Stage 5의 내부 테스트만으로 충분하고, 공개 배포의 관문들은 통과할 필요가 없다.

정책은 자주 바뀐다. 각 항목의 근거는 맨 아래 출처의 공식 문서 링크로 확인할 것.

목적지 정하기 먼저 결정

이 선택 하나가 뒤따르는 작업량을 몇 배로 갈라놓는다. Play에 "올린다"는 말은 실제로 네 가지 서로 다른 상태를 뜻한다.

목적지누가 설치 가능보안 경고추가 관문
내부 테스트 내가 이메일로 초대한 최대 100명 없음 (Play가 설치) 없음 — 심사 대기도 사실상 없음
비공개 테스트 초대한 그룹 없음 프로덕션으로 가려면 12명 × 14일의 근거가 된다
공개 테스트 누구나 (테스터로 참여) 없음 스토어 등록정보 필요
프로덕션 누구나 (정식 검색·설치) 없음 12명 × 14일 + 등록정보 + 심사 전부
핵심 개인이 자기 폰에서 경고 없이 쓰는 것이 목적이면 내부 테스트에서 끝난다. $25 계정과 신원 확인, AAB 빌드까지만 하면 되고, 12명 테스터·스크린샷·피처 그래픽·심사는 전부 건너뛴다. 나중에 마음이 바뀌면 같은 계정에서 위 단계로 올라가면 된다.

Stage 0 · 되돌릴 수 없는 결정 시작 전

아래 세 가지는 한 번 정하면 사실상 못 바꾼다. 계정을 만들기 전에 정해야 하는 이유가 여기 있다.

① 계정 유형: 개인 vs 조직

왜 중요한가: 2023년 11월 13일 이후에 만든 개인 계정에만 "12명 테스터 × 14일" 요건이 붙는다. 조직 계정은 면제된다. 계정 유형은 나중에 바꾸기가 매우 번거롭다.

조직 계정은 D-U-N-S 번호(무료로 발급 가능하나 사업자 실체가 필요)와 회사 웹사이트 확인을 요구한다. 개인이 이걸 우회하려고 없는 조직을 만드는 건 정책 위반이다.

② 패키지명 (applicationId)

왜 중요한가: Play에서 앱의 영구 식별자다. 한 번 업로드하면 영원히 못 바꾼다. 바꾸려면 완전히 다른 앱으로 새로 출시해야 하고, 기존 설치 사용자는 따라오지 않는다. 삭제한 앱의 패키지명도 재사용할 수 없다.

역방향 도메인 형식으로, 소유한 도메인이나 GitHub 계정 기반으로 짓는다. 예: dev.jwjnick.renderext

③ 앱 서명 키

왜 중요한가: 안드로이드는 "같은 키로 서명된 것"만 같은 앱의 업데이트로 인정한다. 키를 잃으면 그 앱은 영원히 업데이트할 수 없다.

그래서 신규 앱은 Play 앱 서명(Play App Signing)이 필수다. 구조는 이렇다:

  • 업로드 키 — 내가 만들어 보관. AAB에 서명해 Play Console에 올릴 때 쓴다. 분실해도 Google에 재설정을 요청할 수 있다.
  • 앱 서명 키 — Google이 보관. 실제 사용자 기기에 배포되는 최종 서명. 내가 잃어버릴 일이 없다.
주의 업로드 키스토어와 비밀번호는 별도로 백업할 것. CI에서 서명한다면 키스토어를 base64로 인코딩해 GitHub Secrets 같은 비밀 저장소에 넣고, 절대 저장소에 커밋하지 않는다.

Stage 1 · 개발자 계정과 신원 확인 1~수일

Play에 무엇이든 올리려면 반드시 통과해야 하는 관문. 돈과 신분증이 필요한 유일한 단계다.

  • 등록비 $25 — 1회, 평생. 앱 개수 제한 없음.
  • 신원 확인 — 개인은 법적 이름·주소·이메일·전화번호, 필요 시 정부 발급 신분증. 조직은 D-U-N-S 번호와 웹사이트 확인.
  • 개발자 인증(Android developer verification) — 2026년부터 Play Console과 Android Developer Console의 전 개발자로 확대된 별도 절차. 신원 확인에 더해 패키지명 등록(내 키로 서명한 APK를 제출해 소유권 증명)이 포함된다.

왜 이렇게 됐나: 악성 앱과 사칭을 줄이기 위해 "앱마다 책임질 실명 주체"를 두겠다는 방향이다. 뒤의 사이드로딩 변화도 같은 정책의 일부다.

Stage 2 · 빌드 산출물 개발 작업

개인 배포용 APK와 Play용 산출물은 형식부터 다르다. 여기가 코드/빌드 설정을 실제로 고쳐야 하는 유일한 단계다.

AAB (Android App Bundle) — APK 아님

신규 앱은 APK를 업로드할 수 없고 AAB만 받는다. (./gradlew bundleRelease)

왜: AAB는 완성된 설치 파일이 아니라 "재료 묶음"이다. Play가 이걸 받아 각 기기의 화면 밀도·CPU·언어에 맞는 최소한의 APK를 서버에서 생성해 내려보낸다. 사용자 다운로드 용량이 줄어드는 대신, 최종 서명을 Google이 하게 되므로 Play 앱 서명이 강제된다.

target API level

매년 상향된다. 기준일 현재:

  • 2026-08-31부터 — 신규 앱과 모든 업데이트는 Android 16 (API 36) 이상을 타겟해야 제출 가능. 연장 신청 시 2026-11-01까지.
  • 기존 앱 — API 35 이상을 유지하지 않으면, 앱이 타겟하는 버전보다 높은 Android를 쓰는 신규 사용자에게 노출되지 않는다. 이미 설치한 사람은 계속 쓸 수 있다.

왜: 최신 권한 모델·보안 제약을 앱이 실제로 준수하게 만들기 위해서다. targetSdk를 올리면 동작이 바뀌는 API가 생기므로 단순 숫자 변경이 아니라 회귀 테스트가 필요하다. compileSdk도 함께 올려야 하고, 그러면 Android Gradle Plugin 버전도 따라 올려야 하는 경우가 많다.

versionCode

업로드할 때마다 단조 증가해야 한다. 같은 값은 재업로드 불가. CI에서 빌드한다면 빌드 번호를 그대로 쓰는 방식이 안전하다.

Stage 3 · 앱 콘텐츠 신고 Play Console

코드가 아니라 선언이다. 그런데 반려와 앱 삭제가 가장 많이 발생하는 곳이 바로 여기다 — 잘못 신고하면 정책 위반이 된다.

항목필수 여부왜 / 주의
데이터 보안
(Data safety)		 전 앱 필수 수집·공유하는 데이터를 스토어에 공개 표시한다. 실제 동작과 다르면 정책 위반. 아무것도 수집하지 않는 앱은 "수집 없음"으로 신고하면 되고, 이게 가장 통과가 쉽다.
개인정보처리방침 조건부 민감한 권한·데이터를 다루거나 아동을 대상으로 하면 필수이며, 활성 URL이어야 한다. 해당 없어도 한 장 만들어 두는 편이 심사에서 마찰이 적다 (GitHub Pages로 충분).
콘텐츠 등급 필수 설문에 답하면 등급이 산정된다. 작성하지 않으면 'Unrated'가 되고 삭제될 수 있다.
타겟 연령층 필수 아동을 포함하면 Families 정책이 추가로 적용된다 — 광고·SDK 제약이 크게 늘어난다.
광고 포함 여부 필수 서드파티 광고 SDK를 통한 것도 포함. 있다고 신고하면 스토어에 "광고 포함" 라벨이 붙는다.
정부·금융·뉴스·건강 등 해당 시 카테고리별 추가 신고와 증빙이 요구된다.
권한이 적을수록 유리하다 선언할 게 없는 앱이 가장 빨리 통과한다. 필요 없는 권한(특히 INTERNET, 저장소, 위치)을 매니페스트에서 빼는 것만으로 이 단계 전체가 단순해진다.

Stage 4 · 스토어 등록정보 공개 배포만

내부 테스트만 할 거면 이 단계는 통째로 건너뛴다. 공개(공개 테스트·프로덕션)에서만 필요하다.

자산규격
앱 아이콘512 × 512 px · 32비트 PNG(알파 포함) · 최대 1024 KB
피처 그래픽1024 × 500 px · JPEG 또는 24비트 PNG(알파 없음)
폰 스크린샷 최소 2장, 기기 유형당 최대 8장 · 각 변 320~3840 px · 긴 변이 짧은 변의 2배를 넘을 수 없음 · 세로 9:16 / 가로 16:9 · JPEG 또는 24비트 PNG(알파 없음)
앱 이름30자
간단한 설명80자
자세한 설명4,000자

Google의 추천·홍보 대상이 되려면 1080 px 이상 스크린샷 4장 이상이 권장된다.

Stage 5 · 트랙과 관문 여기가 진짜 벽

개인 개발자가 공개 배포에서 실제로 막히는 지점은 심사가 아니라 테스터 모집이다.

트랙규모속도프로덕션 요건 기여
내부 테스트 최대 100명 (이메일로 지정, 최소 인원 없음) 심사 대기 없이 수 분 내 반영 기여하지 않음 — 몇 명을 며칠 넣든 무관
비공개 테스트 이메일 목록 또는 Google 그룹 검토 있음 여기서만 카운트된다
공개 테스트 제한 없음 검토 있음 스토어 등록정보 필요
12명 × 14일 규칙 2023년 11월 13일 이후 만든 개인 계정은, 프로덕션 접근을 신청하려면 비공개 테스트에 최소 12명이 옵트인한 상태로 연속 14일을 채워야 한다.

· 14일 카운트는 12번째 테스터가 참여한 시점부터 시작한다. 중간에 인원이 12명 아래로 떨어지면 곤란해진다.
· 원래 20명이었으나 2024년 12월 11일 12명으로 완화됐다.
· 조직 계정, 또는 2023-11-13 이전에 만든 개인 계정은 면제된다.
· 내부 테스트로는 절대 이 요건을 채울 수 없다.

왜 이런 규칙이 생겼나: 심사만 통과하고 버려지는 저품질·사기성 앱이 개인 계정에서 쏟아지자, "최소한 실제 사용자 손에서 2주는 돌려본 앱"만 공개하도록 만든 장치다. 그래서 테스터는 실제로 앱을 설치한 서로 다른 계정이어야 한다.

Stage 6 · 심사와 출시 대기

  • 모든 신고와 등록정보를 채운 뒤 검토를 제출한다.
  • 신규 개인 계정은 첫 심사가 특히 오래 걸릴 수 있다(수일 단위). 이후 업데이트는 짧아진다.
  • 거절되면 사유가 통보된다. 대부분 Stage 3의 신고 내용과 실제 앱 동작의 불일치다.
  • 단계적 출시로 일부 사용자에게 먼저 배포해 문제를 확인한 뒤 100%로 올릴 수 있다.

Stage 7 · 출시 후 계속 지는 의무 매년

Play는 "한 번 올리면 끝"이 아니다. 방치하면 스스로 내려간다.

  • 매년 target API 상향 — 따라가지 않으면 신규 사용자에게 노출이 중단되고, 더 지나면 업데이트 제출 자체가 막힌다. 앱을 안 고칠 생각이어도 1년에 한 번은 빌드해서 올려야 한다.
  • 정책 변경 대응 — 새 신고 항목이 생기면 기한 내 채워야 한다.
  • 장기 미업데이트 앱은 검색 노출이 제한되거나 제거될 수 있다.
개인 프로젝트라면 이 비용을 먼저 계산할 것 공개 배포는 "무료로 남에게 주는 것"이 아니라 매년 유지보수를 약속하는 것이다. 그럴 생각이 없다면 GitHub Releases + 내부 테스트 조합이 오히려 정직한 선택이다.

사례 · render-ext는 지금 어디까지 됐나 2026-08

실제 앱에 위 단계를 대입하면 남은 작업이 구체적으로 드러난다.

즉 내부 테스트까지는 빌드 설정 세 줄기(AAB·서명·targetSdk)만 손보면 된다. 공개 배포로 가려면 여기에 Stage 3·4·5가 전부 붙는다.

사이드로딩의 미래 Play에 안 올려도 영향

"그냥 APK로 계속 쓰면 된다"가 언제까지 유효한지 알아야 판단할 수 있다.

  • 2026년 8월 — 미인증 앱 설치 시 24시간 대기가 포함된 "고급 설치 흐름"이 전 세계로 확대. 동시에 학생·취미 개발자용 무료 계정이 정식 출시됐다.
  • 2026-09-30 — 브라질·인도네시아·싱가포르·태국에서, 인증된 개발자가 등록하지 않은 앱은 인증 기기(Play Protect 탑재)에 설치·업데이트가 차단된다.
  • 2027년 — 전 세계로 확대 예정.
  • ADB를 통한 설치는 계속 예외로 남는다.

무료 Limited Distribution 계정

비용도 정부 발급 신분증도 없이 이메일만으로 만들 수 있고, 앱 개수 제한 없이 최대 20대 기기에 배포할 수 있다. 공개 스토어 출시용은 아니다.

오해하기 쉬운 점 이 계정은 사이드로딩을 계속 허용받는 수단이지, 설치할 때 뜨는 "출처를 알 수 없는 앱 허용" 프롬프트를 없애 주지 않는다. 그 프롬프트가 사라지는 건 Play가 설치를 대행할 때뿐이다.

판단 기준: 본인과 소수만 쓸 앱이면 무료 계정으로 인증만 받아 두면 2027년 이후에도 안전하다. 경고 없는 설치 경험까지 원하면 $25 계정 + 내부 테스트. 남들이 검색해서 받게 하려면 그때 비로소 프로덕션까지 간다.
