Using VC Analyzer

Pick a frame on the timeline, then click any block. The inspector shows its prediction, transform and motion data, the partition decisions above it, and every entropy-decoded symbol attributed to it with its cost in bits.

Keys

← →Previous / next frame (in the order chosen on the Frame tab)
m r q b s nFill blocks by mode, reference, qindex, bits, skip, or no fill
w fAfter vca arch: fill superblocks by estimated HW cycles, blocks by reference fetch per pixel. Provisional: placeholder parameters, see ARCH_MODEL.md
g t v pToggle block grid, transform grid, motion vectors, superblocks and tiles
0 1 + −Fit, 1:1, zoom in, zoom out. Drag to pan, wheel to zoom.
Shift+←→↑↓Select the neighbouring block. The x, y box selects the block at a pixel; e selects the costliest block.
cCopy the selected block as context for an AI assistant
d xDiff mode: toggle mismatch outlines; flip the picture between A and B

Comparing two decoders

Serve a reference analysis (A) and one from a C model or RTL dump (B). The page opens on the first mismatch: the frame, the pixel stage where the two diverge first, and the block holding the first differing sample. The Diff tab lists every stage, block and symbol that differs.

python -m vca serve ref.vca cmodel.vca --diff
python -m vca export ref.vca -o bundle/ --diff cmodel.vca

Your own streams

Analyze locally with the command line, then either serve it or export a bundle and open the folder here. The page reads the folder in your browser; nothing is uploaded.

python -m vca analyze stream.ivf --pixels all
python -m vca serve stream.vca
python -m vca export stream.vca -o bundle/

Pixel stages come from the reference decoder: recon is the output after in-loop filters, prefilter is the reconstruction before them, pred is the prediction. Coordinates are luma pixels; motion vectors are in 1/8 pel.
