Using VC Analyzer

Pick a frame on the timeline, then click any block. The inspector shows its prediction, transform and motion data, the partition decisions above it, and every entropy-decoded symbol attributed to it with its cost in bits.

HW model (draft)

The HW tab of the inspector shows the provisional L0 HW model of the open analysis: for this frame and the whole stream the cycle budget, the estimated cycles and utilization, the slowest module, the clock it would need and the peak memory bandwidth. Its numbers come from placeholder parameters unless you load your own config (see ARCH_MODEL.md).

With the local GUI (vca serve) the tab also edits the config: change a value (each label's tooltip says what it means; values that differ from the example are marked "changed"), then Recalculate. The w and f fills and the tab update when the job ends, on the same frame and block. Compare as B runs the edited config next to the current one and lists the cycles of both frame by frame. Configs can be saved by name, loaded, imported from a YAML file and downloaded as YAML for python -m vca arch --config. The public demo site shows the config read-only.

Comparing two decoders

Serve a reference analysis (A) and one from a C model or RTL dump (B). The page opens on the first mismatch: the frame, the pixel stage where the two diverge first, and the block holding the first differing sample. The Diff tab lists every stage, block and symbol that differs.

python -m vca serve ref.vca cmodel.vca --diff
python -m vca export ref.vca -o bundle/ --diff cmodel.vca

In the local GUI, Compare (a, or "Compare with…" on a Library row) does the same without a command line. A is an analysis of the Library. B is another analysis of the same codec, a C model or RTL dump read through its mapping file (10_ir/DUMP_MAPPING.md; python -m vca dump-example writes an example), or one raw YUV file of output pictures with 8-bit or 16-bit little endian samples, whose size is checked against A first. A dump or a YUV file becomes an analysis in a job, and the comparison opens when the job ends. Comparisons are listed in the Library as "A vs B"; Remove takes the comparison away and keeps both analyses. When the dump gives each block a simulation time, the Diff tab shows it for the first mismatching block.

Your own streams

Start the local GUI with python -m vca serve (or give it a stream file: python -m vca serve clip.mp4). Then press Open stream (o), choose a file, drop one on the window, or paste its path. The page shows the codec, size and frame count first; Analyze runs the reference decoder's dumper, builds the store and the HW model draft, and opens the result. The job list at the bottom right shows each phase, and Cancel removes what a job wrote so far. Containers (MP4, MKV, WebM, TS) are unpacked with FFmpeg first.

After the picture opens, the output is checked against the reference decoder in the background; the job list and the Library show the result. Every analysis is kept in the workspace folder until you delete it in the Library (l).

The same from the command line, for scripts or a machine without a browser:

python -m vca analyze stream.ivf --pixels all
python -m vca serve stream.vca
python -m vca export stream.vca -o bundle/

"Open bundle" reads an exported folder in your browser; nothing is uploaded. Opening and analyzing streams needs the local GUI; the public demo site shows only its examples.

Pixel stages come from the reference decoder: recon is the output after in-loop filters, prefilter is the reconstruction before them, pred is the prediction. Coordinates are luma pixels; motion vectors are in 1/8 pel.
