workflow agent system: 순서는 코드가, 판단은 LLM이 맡는다

LLM 하나에게 "끝까지 해 줘"라고 맡기면 끝·경계·근거가 흐려진다. 그래서 순서와 멈춤은 결정론 프로그램이 지키고, LLM은 자기 칸의 판단과 작업만 한다. 자율 선언은 글이 아니라 실행 중 허용 목록이다.

1. 부품 지도

2. task 폴더 파일과 계약: 단계 하나에 파일 하나

3. 자율 선언은 두 겹으로 지킨다

4. 세션은 소모품, STATE가 정본

5. 세 hard-zero: 하나라도 나오면 그 변경을 되돌린다

hard-zero뜻어디서 세나
경계 넘기 0선언·권한 범위·sandbox 밖의 행동(세션이 묶인 phase의 행동 밖 포함), 고정 항목(port·parameter)이 비교 기준(run 시작 전 또는 확정된 spec 판)과 달라짐, 되돌리기 어려운 행동(MR 생성·ticket 상태 변경·외부 발송·정본 수정), 판정형이 대상을 고침, reject 뒤 재시도(실패했거나 진행 중인 자동 수정이 있는 지적에 자동 수정을 다시 여는 것 포함)guard 기록 · 경계 확인(CB) · golden의 never
근거 없는 판정 0근거 자격 없는 결과가 evaluator 등급으로 근거표에 들어감, 보지 못한 것이 통과로 적힘, LLM이 계산 칸을 씀결과 패키지 검사(CR) · evaluator adapter
사람 기록 훼손 0시스템이 검수 판정·ledger의 사람 칸(waiver·이의·답)·공개 기록·STATE의 사람 줄을 고침record writer · controller 권한

6. 회사에서 세우는 순서

단계하는 일끝났다고 보는 조건(숫자 공란)
0 준비공통 골격·작업 모양 일곱을 정본에 두고, 첫 특화를 회사 checklist·절차서로 채운다(checkpoint로 다시 쓴다). evaluator 목록·policy·권한 범위·records 위치resolver 전체 검사 오류 0
1 뼈대계약 열하나, controller·resolver·policy·evaluator adapter(LLM 없이)해석 사례 전부 일치, 한 바퀴 사례의 결정론 칸 전부 일치
2 판단 agentplanner·worker·result writer·hitl manager·learner, guard(권한 규칙·hook)를 선언에서 생성한 바퀴 사례에서 hard-zero 0
3 첫 갈래 자율첫 카테고리를 열고 posture는 draft부터검수 기록이 쌓이고 reject의 원인이 산출물 쪽으로 옮겨 감
4 판정형·실험형RTL review: A만(사람) → CI 빠른 preset(intake가 CI 리뷰 요청을 받아들인 뒤) → 전체 + 자동 수정(끔 → 일괄 승인 → 자동. 일괄 승인은 intake가 후속의 부모 참조를 나른 뒤, 자동은 on-result까지 받아들이고 노드가 full일 때). 노드는 실적이 쌓이기 전 draft(GATE는 알림만). 합성 matrix와 records(run별 잠정 → 검수 뒤 확정)판정형 도입 단계의 진입 조건
5 조립과 사슬preset을 넓히고 사슬 link를 연다. 정본 승격은 dry replay 첨부안건마다 replay 레포트
