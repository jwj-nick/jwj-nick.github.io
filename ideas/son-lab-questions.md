## 3. "10년 가는 좋은 구조" 5원칙 ★★ (Nick이 요청한 핵심)

1. **콘텐츠 = 데이터 (코드 아님)** — 공부거리 올리기 = md/JSON 추가. "쉽게 쉽게 올리고 만들고"의 토대. 엔지니어링 없이 늘어남.
2. **데이터는 소유·영속·내보내기** — Supabase(Postgres) + 항상 export 가능. *"사라지지 않게."* 절대 lock-in 안 됨.
3. **모듈 플러그인** — manifest 레지스트리. 모듈 추가가 국소적. 나중에 아들이 모듈을 끼움.
4. **안정 코어 + 진화 엣지** — 작은 불변 쉘(auth·nav·데이터층)은 거의 안 바뀌고, 모듈·콘텐츠는 끝없이 바뀜. **10년 생존법.**
5. **시스템 자체가 교재** — CS/코딩 트랙의 정점 = *아들이 자기 허브에 모듈을 추가*. `사용 → 콘텐츠 → 모듈 → 코어` 저작 사다리 = "시스템·하네스 갖추고 진화"를 몸으로.
