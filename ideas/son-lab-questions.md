## 2. 내가 제안하는 방향 ★ (핵심)

> **아들 허브 = 새 4번째 앱이 아니다. LearningSystem이 만들어내는 "첫 완성 인스턴스"로 세우고, 흩어진 것을 모듈로 흡수한다.**

- **한 허브 쉘 + 5모듈**: ① 자기관리·대시보드(할일/루틴) ② **성장기록(아들 전용·사적)** ③ 과목학습(오답·수행평가·퀴즈) ④ 영어 ⑤ 공부거리 탐구
- **엔진** = LearningSystem `se_*` 스킬 그대로 (이미 있음 → 일관성)
- **스택** = **Vite+React+TS+Supabase로 표준화** (3개 중 2개가 이미 이 스택). "무겁다"는 *UX 문제*였지 스택 문제 아님 → 쉘은 **단순·문서화 우선**(인계 위해)
- **데이터** = **아들 소유 Supabase 1 프로젝트**, 단일 스키마
- **소유/인계** = 아들 github + Supabase, Nick+NCC가 빌드 → 몇 년 후 아들이 인수
- **diary-app(가족)은 유지**, 아들 성장기록은 허브로 **분리**(사적)
- **E 완성 → F(딸)는 같은 코어 복제** = LearningSystem 일반화 목표의 실현

> 이 방향이 곧 VISION의 *"아이가 직접 만드는 80% 자동생성"*의 첫 결실. E=1호 인스턴스, F=2호.

## 3. 결정 질문 (Nick 의견 주실 것) — 각 ★는 내 추천

**먼저 — 방향 잠그는 4개 (D1~D4):**

- **D1. 통합 범위** — high1·영어를 허브 모듈로 **흡수** vs **링크만**? ★ *high1은 흡수, 영어(02_App_Eng)는 이미 성숙앱이라 1차는 링크/임베드 → 점진 흡수.*
- **D2. 가족 diary-app** — 아들 성장기록을 허브로 **분리** vs 가족앱에 유지? ★ *분리(아들 사적). 가족앱은 공유용으로 그대로.*
- **D3. 스택** — **Vite+React+TS+Supabase 표준화**? ★ *예(일관·인계·노하우 재사용).* — 대안: 바닐라+Supabase 클라이언트(빌드X, VISION '단순'에 충실하나 큰 허브엔 구조 부족). **큰 허브라 React 추천**, 쉘만 단순하게.
- **D4. 위치 규정** — 허브를 **LearningSystem의 인스턴스**로(E=1호, F=2호)? ★ *예 — 이게 통일 서사.*
