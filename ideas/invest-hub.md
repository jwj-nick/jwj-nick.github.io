## 1. 존재 의미 — 왜 이 앱이어야 하나 ★

- **푸는 문제:** *"책·유튜브 엄청 봤지만 계속 소비만 하고 자산화 못했다."* — 소비가 증발하는 구조를, **소비가 곧 복리 자산이 되는 구조**로 바꾼다.
- **이것은 ___ 이다:** 내 투자 지혜·판단·기록이 **한 곳에 쌓이고 복리로 자라는 개인 의사결정 시스템.**
- **이것은 ___ 가 아니다:** 증권 거래앱(X) · 단순 노트앱(X) · 시세 위젯(X). → 거래가 아니라 **판단의 질**을 높이는 도구.
- **없으면 잃는 것:** 매년 본 수백 시간의 콘텐츠가 매년 증발. 같은 실수 반복. 폭락장마다 감정에 휘둘림.

## 2. 지속 활용 설계 — 안 죽게 ★

> 개인 도구 1위 사망 원인 = **방치.** 처음부터 안 죽도록 설계한다.

- **마찰 0:** 소비 → 자산화가 거의 자동 (URL 붙이면 AI가 초안). 귀찮으면 안 씀.
- **쓸수록 이득, 안 쓰면 손해:** 기록이 복리로 쌓여 다음 판단에 쓰임. → 안 쓰면 내가 손해라는 구조.
- **실제 의사결정에 박힘:** 결정저널·폭락 플레이북은 *진짜 살 때·팔 때* 꺼내봄 = 장식 아님.
- **리듬:** 주간 시장노트 / 월간 포트폴리오 / 분기 thesis 재점검 / 연간 회고.
- **폰 우선:** 틈날 때 보고 한 줄 넣게.

## 3. 진화 — 개인 → 가족 → 아이 → (유튜브) ★

| 단계 | 누구 | 무엇 | 프라이버시 |
|---|---|---|---|
| **A. 개인** | 나 | 전체(지식·판단·보유) | 전부 private |
| **B. 가족 공유** | 가족 | *지식층만* (재해석한 원칙·시장이해) | 보유·계좌 영원히 차단 |
| **C. 아이 공부** | 아이들 | 경제·금융·투자 리터러시 (현명한 투자법·역사) | 아이 허브(E/F)와 연결 |
| **D. (선택) 유튜브** | 공개 | **재해석한 내 콘텐츠가 중요 축** | 지식층만, 보유 절대 X |

> **핵심:** 이 진화는 **2단 프라이버시(P7)** 위에서만 성립 — *지식층은 나눌 수 있고, 보유는 영원히 안 샌다.* 그래서 P7은 단순 보안이 아니라 **이 앱의 미래를 여는 구조.**

## 4. 핵심 원칙

- **소비 → 자산화** (존재 이유)
- **재해석·흡수** — 저작권 자료·기존 역사앱 모두 *내 언어로 재해석해 녹임*. 링크/복붙 금지. (재해석분 = 내 자산 → 가족·유튜브로 갈 수 있음)
- **실투자정보 절대 private** (2단 분리)
- **콘텐츠 = 데이터, 소유·영속·export** (lock-in 금지)
- **엔진은 콘텐츠가 당김(P1) · NCC 자율 점진 개선(P2)** — 다른 Lab과 공유

## 6. 핵심 메커니즘 P1~P10 (전부 — 이 앱을 "좋은 서비스"로 만드는 것) ★

> *무엇 / 왜 / 어떻게.*

- **P1. 결정 저널** — 모든 매수·매도를 *논리+감정+시장상황*과 함께. / 내 실수 패턴을 데이터로(실력향상 최강 수단). / 거래마다 한 장 엔트리, 나중에 복기·캘리브레이션 입력.
- **P2. Thesis + 무효화 트리거** — 종목마다 "믿는 이유" + "틀렸다는 증거". / 종목 편애 방지. / 인제스천이 뉴스를 트리거에 대조 → 알림.
- **P3. 폭락장 플레이북(사전 약속)** — −20%/−40% 행동을 *미리* 규칙화. / 닥치면 감정이 지배. / "유리 깨고 꺼내는" 체크리스트 + 현금·매수 후보 사전 지정.
- **P4. 매크로 → 마이크로 전파** — 매크로 관점(금리·유동성)을 *영향 섹터·종목*에 연결. / "종합적으로 놓고 보기". / 지식 그래프 엣지로, 인사이트 1개가 관련 thesis에 플래그.
- **P5. AI 데블스 애드버킷** — 내 thesis에 AI가 *베어 케이스 공격*. / 확증편향 레드팀. / thesis 저장 시 자동 반론 1쌍 생성.
- **P6. 출처 신뢰 등급** — 입력마다 등급(책>검증 애널>일반 유튜버). / 품질로 가중, 쓰레기 차단. / 카드·원칙에 출처 등급 태그.
- **P7. 2단 프라이버시** — ① 공개 가능 *지식층* ② 절대 비공개 *보유·계좌·수익*. / 가족·아이·유튜브 진화의 전제(§3). / 데이터 모델부터 두 층 분리.
- **P8. 원칙 SR** — 명언·원칙 카드 주기적 재등장. / 지혜가 바래지 않게. / study-quiz SR 엔진 재사용.
- **P9. 리뷰 리듬** — 주/월/분기/연 정기 리뷰. / 살아있는 시스템(§2). / 각 리듬마다 자동 프롬프트·요약.
- **P10. 캘리브레이션** — 예측에 확신도(%) 적고 나중에 적중률 측정. / 내 과신 지점을 안다. / 결정저널과 연동, 분기 캘리브레이션 리포트.

## 7. 인제스천 워크플로우 (핵심 엔진 `invest-ingest`)

## 8. 주의점 / 함정 ★ (잘 정리 — Nick 요청)

**투자 자체의 함정**
- **지표·백테스트 착각** — 과최적화·후견편향·생존편향. 좋아 보이는 숫자 ≠ 미래.
- **확증편향·종목 편애** — P5(데블스)·P2(무효화)로 방어.
- **과신** — 캘리브레이션(P10) 없이 기록만 하면 자기기만.
- **행동 함정** — FOMO·손실회피·군중심리. 급등·폭락에서 P3로 방어.
- **메트릭 해킹** — 보기 좋은 지표만 보지 않기 (PQO 교훈을 투자에).

**시스템·도구의 함정**
- **도구질로 회피** — 엔진을 미리 다 만들고 공부 안 함. P1 원칙(콘텐츠가 당김) 위반.
- **방치** — §2 지속활용 설계가 방어선.
- **저작권** — 재해석만, 원문 복붙·게시 금지.
- **프라이버시 유출** — 2단 분리·API키 로컬·가족/유튜브 공유 시 보유층 차단.
- **lock-in** — 데이터는 항상 export 가능.
- **"조언" 아님** — 본인 의사결정 보조. 책임은 본인. (가족·아이 공유 시 특히 명시)

## 10. 열린 질문 (마스터플랜 레벨)

- **가족/아이 공유 범위** — 지식층 어디까지? 아이 허브(E/F)와 어떻게 잇나?

- **지식 체계의 1차 골격** — 투자 철학·원칙을 어떤 분류 체계로 담을까(가치/매크로/행동/리스크…)?

## 11. 구현 메커니즘 — 마찰 0 + 폰 우선 (초기 → 진화 → 장벽) ★

> 설계 핵심: **캡처(즉시·폰) / 처리(비동기·서버 AI) / 검토(아무때나)** 를 분리. 그래야 "틈날 때 1탭"이 진짜 0 마찰.

### 11-1. 초기버전 (0차 — 개인 서버 전, 검증용) ★ NotebookLM 브릿지
- **캡처+추출:** **NotebookLM**에 소스(유튜브/PDF/기사) 추가 → 자막·요약·핵심주장 추출. *(서버 자막추출·whisper·IP차단 통째 우회. 멀티소스 한 도구.)*
- **큐레이션(손):** NotebookLM 출력에서 자산화할 핵심주장 선택
- **라우팅:** Claude Code 스킬 `invest-ingest` — 선택 텍스트를 *내 시스템에 비춰* 라우팅·카드 초안 → 데이터 파일
- **저장:** 로컬 파일/JSON · 실계좌 X
- **분담:** NotebookLM=소스 이해 / 내 엔진=내 지식과의 관계 라우팅.
- ⚠️ **수동은 철학이 아니라 임시 부채** — 지금 환경에서 자막추출 자동화가 안 되니 불가피한 stopgap. 목표는 **마찰 0 자동화**, 전사 API/개인 서버 생기면 즉시 대체.
- **공유 추출 front-end** = A·C·J·K 지식 허브 + 깊이 공부(스펙 PDF Q&A) 공통.

### 11-2. 진화 방향
1. **개인 앱서버** — 인제스천 워커(fetch + 자막추출 + 임베딩 + LLM) + Supabase
2. **PWA** — Share Target(1탭 캡처) · 오프라인 퀵캡처(IndexedDB 큐→동기화) · 검토 UI
3. **실계좌/증권 API** — 맨 끝, 성숙 후
4. **가족 → 아이 → 유튜브** — 2단 프라이버시(P7) 위에서

### 11-3. 넘어야 할 장벽

| 장벽 | 왜 어렵나 | 완화 |
|---|---|---|
| 유튜브 자막 추출 | 자동자막 부재·언어·ToS | **초기 NotebookLM 브릿지(수동)** → 후기 전사 API/개인서버 |
| AI 라우팅 품질 | 환각·잘못된 thesis 영향 판단 | RAG 컨텍스트 + **사람 검토 게이트** + 출처등급(P6) |
| 검토 병목 | 초안 쌓이면 검토가 일 | 고등급·저영향은 **자동승인 임계**, 나머지만 검토 |
| 프라이버시 | 키·보유 누수 | 키 **서버 only**, RLS 2단 분리, export |
| 개인 서버 운영 | 가동·보안·백업 | 단순 스택, 자동 백업, 비공개 |
| 데이터 수명 | 스키마 10년 가야 | 콘텐츠=데이터, export 우선, 마이그레이션 여지 |
| LLM 비용 | 호출 누적 | 배치·캐시·작은 모델로 1차 라우팅 |
