## 2. 두 기둥 ★ (Nick이 지정한 두 축)

### 기둥 1 — Codec A-to-Z 지식 척추 (Knowledge Spine)
> 비디오 코덱 전체를 담은 종합 지식. 커리어의 척추.

- **범위 = 파이프라인 × 표준 × 체험지**
  - 파이프라인: intra/inter prediction · ME/MC · transform(DCT/DST/정수변환) · quantization+RDO · entropy(CAVLC·CABAC·rANS) · in-loop filter(deblocking·SAO·ALF·CDEF·loop restoration) · DPB/참조관리 · rate control · film grain · reconstruction
  - 표준 축: H.264/AVC → HEVC → VP9 → **AV1** → VVC → **AV2**(진행 중) — "표준이 왜 이 tool을 택했나"의 진화사
  - **체험지(해자)**: 설계 trade-off, IP화할 때의 함정, 면적/전력/타이밍 현실, war stories — *교과서에 없는 것*
- **형식**: 지식그래프(I46) 기반 + 챕터(uvm-drill 규약). 개념끼리·표준끼리 링크된 백과(=codec "codex")
- **워크플로우**: 새 스킬 **`codec-elicit`** — 인터뷰→구조화→레퍼런스 검증→도전→챕터화

### 기둥 2 — Tool Forge (각 tool HW 설계 + 검증)
> 각 sub-function을 직접 RTL 설계하고 검증환경을 갖춘다.

- **단위 = tool**: 예) 정수변환 · 양자화 · CABAC/엔트로피 · 디블로킹/SAO/ALF · ME/MC · intra pred …
- **각 tool 라이프사이클**: 스펙 → **RTL 설계** → **UVM 검증환경**(TB·레퍼런스 모델·커버리지·assertion)
- **재사용**: 기존 `uvm-*` 스킬군 + `uvm-drill` 그대로. 검증 결과·발견이 **기둥 1에 환류**
- **연결**: cat C #19(UVM 종합 사이트) · 20_UVM_Study(learn-in-public)

## 3. 두 기둥 맞물림

- **Forge → Spine**: tool 하나 설계·검증하면 그 과정의 깊은 이해가 척추에 환류 (설계해봐야 진짜 안다)
- **Spine → Forge**: 척추가 "어느 tool이 핵심·재밌·면접가치 높은가"를 알려줘 forge 우선순위 결정
- 한 객체(예: 디블로킹 필터)를 **지식(왜·trade-off) + 구현(RTL·검증) 두 각도**로 — B의 microgpt-hw 다리와 같은 원리

## 10. 성공 기준

- 코덱 파이프라인 전체를 **본인 언어로 A-to-Z** (표준 진화사 포함)
- tool N개를 **직접 RTL 설계 + 검증환경** 보유 (단순 이해 아님)
- 모든 체험지가 **일반화·비기밀** 형태로 안전하게 보존
- 두 기둥 환류 동작 (forge ↔ spine)
