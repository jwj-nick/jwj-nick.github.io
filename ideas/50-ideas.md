## A. NPU / NVDLA 심화 — RTL 아키텍처 + 검증환경 (Nick 핵심축)

> ★ **이 카테고리 전체를 "NVDLA/NPU Lab" 메가 허브로** — H(통합·커리어) + I(방법론·메타) 적용, private-first. 구체 계획 → **NVDLA Lab 탭** (`2026-06-27_nvdla-npu-lab-plan.md`).

**1. ⭐⟳ NVDLA 살아있는 교과서** — `nvdla_analysis`를 블록별 인터랙티브 학습 사이트로.
*무엇:* CMAC·CACC·SDP·PDP·RUBIK을 RTL 워크스루 + 데이터플로우 애니메이션으로. *왜:* 정적 노트는 다시 안 열게 됨 — uvm-drill처럼 "클릭으로 따라가는 구조"여야 깊이가 붙음. *형식:* uvm-drill 챕터 엔진 재사용.

**2. ⭐ NVDLA Test Environment 해부** — `nvdla-vp/sw/hw` 검증환경을 RTL만큼 깊이.
*무엇:* register 시퀀스 → trace → C-model 비교 → 커버리지. *왜:* "어떻게 검증하나"를 모르면 NPU architect가 아니라 설계 일부만 아는 사람. RTL arch + test env를 한 몸으로. *연결:* 20_UVM_Study 방법론.

**3. ⟳ NPU 데이터패스 시각화 도구** — conv→MAC array→accumulate→activation 파이프라인을 단계별로.
*형식:* 재사용 다이어그램 컴포넌트(#44와 연결). *왜:* 타일링·뱅킹을 "그림으로 손에 잡히게".

**4. ⟳ NVDLA ↔ 밑바닥딥러닝 양방향 브리지** — 책의 forward/conv 수식이 RTL 어디에 매핑되는지.
*왜:* Nick의 약점(DL 수학)을 강점(RTL)으로 흡수 — 양방향 링크가 통찰을 만든다.

**5. NPU 아키텍처 비교 스터디** — NVDLA vs Gemmini vs TPU(systolic) vs 상용 데이터플로우.
*무엇:* weight/output/row-stationary, 타일링, 메모리 계층 비교표. *왜:* 한 IP만 보면 "왜 이렇게 설계했나"를 못 본다 — 비교가 곧 통찰.

**6. Systolic Array 직접 설계** — 작은 NxN MAC 어레이를 RTL로 짜고 NVDLA CMAC과 대조.
*왜:* 만들어봐야 trade-off가 몸에 남는다. *형식:* 작은 RTL + 테스트벤치.

**7. NPU 성능 모델 / Roofline 계산기** — 타일·뱅크·대역폭을 슬라이더로 실험하는 앱.
*왜:* utilization이 왜 안 나오는지 직관 — architect의 핵심 감각.

**8. Sparsity & Quantization on HW** — INT8/구조적 sparsity가 면적·전력·정확도에 미치는 영향.
*형식:* paper-study-app(#40) 적용. *왜:* 차세대 NPU의 본진.

*무엇:* 업무별 폴더에 `.claude/skills/`·`agents/`·`CLAUDE.md` 템플릿 — 그 폴더에서 Claude 실행하면 전용 환경 로드. *왜:* 환경이 곧 생산성. 한 번 세팅하면 그 업무는 매번 같은 품질·속도로. *연결:* 이미 검증된 uvm-* 스킬군·LearningSystem 4-layer·paper-study-app 패턴을 codec·NPU·각 업무로 복제.

## J. 최신 반도체 기술 — 데이터 이동 병목 해결 (Nick NPU/시스템 교집합)

> 신규(2026-06-28). compute는 폭증하는데 메모리·인터커넥트가 못 따라감 = **memory/interconnect wall**. 최근 몇 년 패키징·메모리·통신의 진보를 세부 기술까지. NPU 목표와 직결(가속기 주변 시스템).

**52. ⭐ 데이터 이동 병목 큰 그림** — "왜 지금 이게 핵심인가": compute ≫ 대역폭, 전력의 대부분이 데이터 이동.
*형식:* 전체 지도(나머지 기술을 이 프레임에 배치). *왜:* 개별 기술 전에 "무슨 문제를 푸나"부터.

**53. CXL (Compute Express Link)** — PCIe 위 cache-coherent 링크, 메모리 확장·풀링·공유. Type 1/2/3, CXL 2.0/3.x.
*왜:* 메모리 벽을 "용량·공유"로 푸는 축.

**54. Chiplet + UCIe** — 모놀리식 분할, die-to-die, UCIe 표준. AMD Infinity Fabric / Intel EMIB·Foveros.
*왜:* 수율·비용·이종집적 — 가속기 통합의 기반.

**55. Advanced Packaging** — CoWoS(TSMC 2.5D)·interposer·3D(SoIC·hybrid bonding)·InFO.
*왜:* HBM과 가속기를 한 패키지에 붙이는 물리적 토대.

**56. HBM** — 3D 적층 DRAM+TSV, interposer 위 근접 배치. HBM3/3E/**HBM4**, TB/s급.
*왜:* AI 가속기 대역폭의 현재 정답. NPU 설계 직결.

**57. HBF (High Bandwidth Flash)** — NAND 기반 HBM식 적층(SanDisk·SK hynix, 2025~). 용량↑.
*형식:* 지식 정리(신생). *왜:* HBM(대역폭) ↔ HBF(용량) 보완 — 대형모델 추론 메모리.

**58. DPU (Data Processing Unit)** — 네트워크·스토리지·보안 오프로드(NVIDIA BlueField·AMD Pensando·Intel IPU).
*왜:* 데이터센터에서 CPU를 데이터 이동에서 해방.

**59. 광통신 / Co-packaged Optics** — silicon photonics·optical I/O·CPO·LPO, chip/rack 레벨 전기→광.
*왜:* SerDes 한계 너머 — scale-up/out 대역폭·전력의 다음 도약.

**60. ⭐ 가속기 시스템 관점 통합 + 앱** — 위 기술이 NPU 설계·데이터센터에 어떻게 맞물리나 한 그림 + "최신 반도체 기술" 학습 허브 앱.
*연결:* A(NVDLA)·paper-study-app. *왜:* Nick의 NPU 목표를 "칩 안"에서 "랙·시스템"으로 확장.

## K. 기업 분석 & 투자 — 발굴→실사→지표→비교→전략

> 신규(2026-06-28). 관심 산업·투자 적격 기업을 찾아 세부 공부하고, 투자 지표·동종 비교로 전문적으로 평가. 기존 자산: 70_Invest · invest_companies · `equity-scenario-app` 스킬(에스에이엠티 1호).

**61. 관심 산업에서 기업 발굴 (스크리닝)** — 테마(반도체·AI HW·codec 등)에서 후보 추출 기준·리스트.
*왜:* 좋은 질문은 "어떤 기업"부터.

**62. 기업 세부 공부** — 사업모델·해자·밸류체인 위치·재무제표 읽기.
*형식:* paper-study-app식 정독. *왜:* 숫자 전에 사업을 이해.

**63. 투자 지표 체계** — 밸류에이션(PER·PBR·EV/EBITDA)·수익성(ROE·마진)·성장·현금흐름(FCF).
*왜:* 지표를 "세트"로 봐야 왜곡 안 됨.

**64. 동종기업 비교 (peer)** — 멀티플·마진·성장·점유율 비교표.
*왜:* 절대값보다 상대 위치가 기회를 드러냄.

**65. 투자 전략** — 시나리오(강세/기본/약세)·진입·청산·리스크·비중.
*연결:* equity-scenario-app 시나리오 슬라이더. *왜:* 분석이 결정으로.

**66. ⭐ 엔지니어 해자 — 기술 실사** — 반도체·AI HW 기업을 **기술적 깊이로** 평가(J와 교집합). 로드맵·공정·IP 경쟁력을 엔지니어 눈으로.
*왜:* 대다수 투자자가 못 하는 차별점 — Nick의 20년 + NPU 학습이 그대로 우위.

**67. 앱: 기업 분석/시나리오** — `equity-scenario-app` 확장(주가·실적·배당·달력·시나리오).
*연결:* invest_companies(에스에이엠티). *왜:* 분석을 재사용 앱으로.

**68. 투자 지표 대시보드 / 스크리너** — 관심 기업을 한 화면에서 지표·비교·관찰.
