# 전체 실행 전략 — 어떻게 다 만들어 나갈까 (운영 + 로드맵)

> 2026-06-28 · 지금까지 설계한 모든 Lab/허브를 *현실적으로* 굴리는 법. ⚠️ 아이디어 정리.
> 제약: Nick 하루 2–3h · NCC 비동기·자율 무제한 위임 · 병렬 진행 · **2–3개월 내 전부 "기본틀"**.

## 1. 제약 = 설계 출발점

| 자원 | 성격 | 역할 |
|---|---|---|
| **Nick (2–3h/day)** | 희소·대체불가 | **결정·이해·증류·취향·도메인 깊이** |
| **NCC (비동기·자율)** | 풍부·무제한 | **스캐폴딩·초안·리서치·배선·배포** |

→ 전략 = **"NCC가 틀 짓고 / Nick은 결정·증류"** 비율을 극대화. Nick의 2–3h를 배선에 쓰면 망함.

## 2. ★ 가장 큰 레버 — 공통 플랫폼 1개 (8앱 따로 X)

모든 허브가 같은 뼈대를 공유한다:
- 콘텐츠=데이터 · manifest 모듈 · SR 카드 · **인제스천 엔진** · viz 컴포넌트 · 전용 Claude Code 워크스페이스 · 배포 파이프
- **한 번 만들고 → 각 Lab = 인스턴스 + 도메인 데이터.** (= I50 재사용엔진 · I51 전용환경 · paper-study-app/LearningSystem 일반화의 실현)
- **이것이 "2–3개월에 전부 기본틀"을 가능케 하는 유일한 길.** (8개 bespoke = 불가능)

## 4. 운영 방식 (너와 나)

- **Nick 일일 2–3h** = 리뷰·결정·증류 (배선 절대 X)
- **NCC 비동기 배치** = 세션 사이에 스캐폴딩·초안·리서치·배포 자율 진행
- **위임 큐(inbox)** ★ — Nick이 수시로 작업 투척 → NCC 처리 → 다음 세션 리뷰. *(= 보류했던 D 체크앱을 "작업 위임 큐"로 재활용)*
- **WIP 한계** — Nick 깊은 집중은 **1–2개만**(나머지는 NCC 배경). 폭만 넓고 얕아지는 것 방어.
- **워크스페이스 병렬** — 앱마다 자기완결 폴더+repo. NCC는 여러 개 동시, Nick 포커스는 회전.
- **★ 자동화 최대화 / 마찰 0** — 수동 단계(예: NotebookLM 추출)는 *철학이 아니라* 지금 환경이 자동화를 못 받쳐 생긴 **임시 부채**. 환경 되는 대로 자동화로 대체. 손 더 가게 하는 건 목표가 아님.

## 5. 2–3개월 로드맵 (Sprint 0~4, 2주 단위)

## 6. "기본틀"의 정의 (완성 아님 — 기대치 정직하게)

**틀 = 스켈레톤 + 1 proof 모듈 + 배포 + 전용 워크스페이스.** 풀 콘텐츠(NVDLA 전 블록·Codec A-to-Z·아이 10년 OS)는 *수년*. 2–3개월 = **모든 앱이 살아 움직이기 시작 + 1–2개는 깊이 진입.**

## 7. 우선순위 원칙

1. **엔진·플랫폼 먼저** (안 그러면 8번 반복)
2. **이미 움직이는 것 레버리지** (Codec)
3. **커리어 직결** (NVDLA·J)
4. **공유 엔진 쓰는 것 묶기** (K·J 인제스천)
5. **아이(E)는 생활가치** — 늦지 않게, 단 플랫폼 뒤
6. **F는 E의 fork** (마지막)

## 8. 위험 & 방어

| 위험 | 방어 |
|---|---|
| 폭만 넓고 다 얕음 | Nick 깊은 집중 **1–2개 고정**(나머지는 틀만) |
| 플랫폼 과설계(speculative) | P1: 콘텐츠가 당길 때만 엔진 확장 |
| Nick 시간이 배선에 샘 | 배선·리서치·배포는 전부 NCC |
| 8개 동시 = 산만 | WIP 한계 + 스프린트 1–2 포커스 |
| 방치 | 위임 큐 + 주간 리듬 + 상태 대시보드 |

## 9. ★ 또 다른 제안 (내 추가)

- **위임 큐 = 체크앱 재활용** — 수시 원격 의뢰를 한 inbox로, NCC가 비동기 소화.
- **상태 대시보드** — 이 ideas 뷰어에 "각 앱 Sprint/Phase 한눈에" 뷰 추가.
- **일일 통찰 1줄(I48)** — 매 세션 끝 증류 강제(소비형 방지, 전 Lab 공통).
- **2주 스프린트 데모** — 각 스프린트 끝 *작동하는* 데모 1개(추상 계획 방지).
- **"하나는 끝까지" 규칙** — 매 분기 최소 1개는 proof 넘어 **실사용**까지(전부 50%에서 멈추는 것 방지).
- **공통 디자인 시스템** — 허브들이 같은 룩(이미 ideas 뷰어 다크 테마가 씨앗).
