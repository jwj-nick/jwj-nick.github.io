## 1. NVDLA "살아있는 교과서" + 검증환경 해부 ⭐ (50선 #1+#2)

**정의:** `nvdla_analysis`(doc/hw/sw/vp)를 **블록별 인터랙티브 학습 사이트**로 업그레이드 — RTL 아키텍처 *와* test environment를 한 몸으로.

**왜 지금:** Nick 1순위. 정적 노트는 다시 안 열림. "RTL만 아는 사람"이 아니라 "검증까지 아는 architect"가 목표인데 test env가 비어 있음.

**연결 자산:** uvm-drill 챕터 엔진(그대로 복제) · 20_UVM_Study 검증 방법론 · 밑바닥딥러닝 책.

**산출물:** `nvdla-lab`(가칭) 공개 사이트. 블록당 1챕터: TL;DR → RTL 워크스루 → 데이터플로우 그림 → 검증 포인트(register seq→trace→C-model 비교) → checkpoint.

**단계:**
1. 블록 인벤토리·우선순위(CMAC/CACC/SDP/PDP) + 챕터 골격
2. CMAC 1챕터 완성(RTL+데이터플로우+검증 한 세트) = 템플릿 검증
3. nvdla-vp/sw로 "한 conv layer가 어떻게 검증되나" 1 end-to-end 트레이스
4. 나머지 블록 채우기 + manifest → GitHub Pages

**첫 액션(이번 세션):** uvm-drill 구조를 nvdla-lab으로 스캐폴딩하고 CMAC 챕터 TL;DR+골격 1개 작성.

**성공기준:** "이 블록 입력→연산→출력→어떻게 검증하나"를 그림 보며 5분 설명 가능. 6주.

## 2. microgpt-hw 완성 → LLM을 NPU 관점에서 ⭐ (50선 #10+#14)

**정의:** 이미 있는 `microgpt-hw`(rtl/tb)로 **GPT 추론을 HW에서 end-to-end** 돌리고, KV cache·GEMM·attention이 왜 메모리바운드인지 RTL 시각으로 정리.

**왜 지금:** Nick의 정확한 교집합(AI를 직접 RTL로) — **가장 차별화되는 산출물**. "간단 training AI" 요구의 하드웨어 답.

**연결 자산:** `30_HW_Study/microgpt-hw`(이미 rtl/tb/docs 존재) · microGPT(Karpathy) · #1 NVDLA 데이터플로우.

**산출물:** 동작하는 microgpt-hw(추론) + "LLM 추론의 HW 병목" 1페이지 분석(roofline/메모리).

**단계:**
1. 현재 microgpt-hw 상태 점검(어디까지 됐나) — 갭 리스트
2. SW 골든(numpy/nanoGPT) ↔ RTL 출력 비교 테스트벤치
3. 1 토큰 생성 end-to-end 통과
4. attention/GEMM의 사이클·메모리 프로파일 → 병목 1페이지

**첫 액션:** `microgpt-hw` 폴더 실측(rtl/tb/00_META 읽기) → 완성까지 갭 체크리스트 작성.

**성공기준:** HW에서 토큰 1개 생성 + SW와 bit/근사 일치. "왜 LLM 가속기는 메모리가 관건"을 숫자로 설명. 4–6주.

## 3. 오픈소스 LLM 로컬 랩 + LoRA 파인튜닝 ⭐ (50선 #12+#13)

**정의:** ollama/llama.cpp로 7B 로컬 실행 → 양자화(GGUF) 체감 → 작은 데이터로 **LoRA 파인튜닝**(codec/UVM 도메인 봇).

**왜 지금:** Nick "나중에 오픈소스 LLM" 스레드의 첫 단추. HW 엔지니어로서 tok/s·메모리·양자화를 **숫자로** 만지는 게 핵심.

**연결 자산:** 20_Ideas 04_Learning_AI · #2의 NPU 관점 · 스터디 노트(파인튜닝 데이터).

**산출물:** 로컬 LLM 실행 노트 + 양자화 비교표(FP16/INT8/INT4 tok/s·메모리·품질) + 도메인 LoRA 1개.

**단계:**
1. ollama로 7B 실행 + tok/s·메모리 실측(현 PC 기준)
2. GGUF 양자화 3종 비교표
3. 작은 도메인 데이터셋(UVM/codec Q&A) 구성
4. LoRA/QLoRA 1회전 → before/after 비교

**첫 액션:** 로컬 환경 점검(GPU/RAM) → ollama 설치 가이드 + 첫 모델 실행 체크리스트.

**성공기준:** 양자화별 trade-off를 직접 측정한 표 + "내 도메인" 봇이 베이스보다 나음. 3–4주.

## 5. 통합 학습 지도 (내가 선 자리) ⭐ (50선 #36)

**정의:** RTL/HW설계 → 가속기(NPU) → 모델(LLM) 컴퓨팅 스택을 한 축으로, **codec 설계·검증 전문성은 별도 강점 트랙**으로 나란히 둔 1장짜리 지도. 각 노드 숙련도 + "다음 한 걸음" 표시. (codec과 NPU를 억지로 잇지 않음 — 각자 깊게.)

**왜 지금:** 스터디 5개가 흩어져 있음. 지도 한 장이면 **각 트랙의 현 위치·우선순위**가 보임 — 나머지 9개의 뼈대.

**연결 자산:** MEMORY 스터디 표 · 모든 repo · #46 지식그래프와 합류 가능.

**산출물:** 1장짜리 인터랙티브 맵(노드=주제, 엣지=의존, 색=숙련도). "지금 여기" 마커.

**단계:**
1. 노드 목록화(codec/UVM/NVDLA/PQO/LLM/microgpt-hw …) + 의존 엣지
2. 각 노드 숙련도 자가평가(L1/L2/L3)
3. "다음 한 걸음" 경로 1개 강조(예: microgpt-hw→LLM가속기)
4. 살아있는 문서화(분기마다 갱신)

**첫 액션:** ASCII/mermaid로 스택 지도 초안 + 숙련도 색칠.

**성공기준:** "왜 이 순서로 공부하는가"를 지도 한 장으로 설명. 1주(이후 상시 갱신).

## 8. NPU 아키텍처 비교 + 성능 모델 계산기 (50선 #5+#7)

**정의:** NVDLA vs Gemmini vs TPU 데이터플로우 비교표 + **roofline/utilization 계산기 앱**(타일·뱅크·대역폭 슬라이더).

**왜 지금:** 한 IP만 보면 "왜 이렇게 설계했나"를 못 봄. 비교 + 정량 모델 = architect의 핵심 감각. #1을 풍부하게.

**연결 자산:** #1 NVDLA · #44 시각화 컴포넌트 · 밑바닥딥러닝 conv 수식.

**산출물:** 비교표(weight/output/row-stationary·타일링·메모리계층) + 인터랙티브 roofline 앱.

**단계:**
1. 데이터플로우 3종 비교표
2. roofline 수식 정리(연산강도 vs 대역폭)
3. 슬라이더 앱(타일 크기→utilization 변화 시각화)
4. NVDLA 실제 수치 대입 검증

**첫 액션:** 데이터플로우 비교표 초안(3 아키텍처 × 5 항목).

**성공기준:** "왜 utilization이 안 나오나"를 슬라이더로 시연. 2–3주.
